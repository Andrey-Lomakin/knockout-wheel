# AGENTS.md — инструкции для AI-агентов

Руководство по работе с репозиторием «Колесо выбивания» (Vite + React 19 + TypeScript).
Приложение живёт на GitHub Pages: <https://andrey-lomakin.github.io/knockout-wheel/>

## Запуск

```bash
pnpm install
pnpm dev       # http://localhost:5173
pnpm build     # tsc -b && vite build
pnpm lint      # eslint . --max-warnings 0
pnpm test      # vitest run
```

Перед коммитом прогонять **`pnpm lint`, `pnpm test` и `pnpm build`** — ровно то же самое
делает CI перед публикацией, так что упавший линт или тест ломает деплой.

> pnpm 11 блокирует install-скрипт esbuild. Политика задана в `pnpm-workspace.yaml`
> (`onlyBuiltDependencies`) и авто-проверка зависимостей отключена (`verifyDepsBeforeRun: false`).
> Не добавляй `pnpm.onlyBuiltDependencies` в `package.json` — pnpm 11 это поле не читает.

## Структура проекта

Проект собран из маленьких модулей по слоям:

```
src/
  main.tsx                 # точка входа (StrictMode)
  test/setup.ts            # общая настройка тестов: cleanup RTL, заглушки ResizeObserver и canvas
  index.css / App.css      # глобальные стили + тема
  App.tsx                  # композиция страницы + приём шаринг-ссылки
  game/                    # бизнес-логика и данные
    types.ts               # типы: Weight, Participant, Podium, WheelParticipant
    constants.ts           # веса, длительности, пауза авто-спина, ключ хранилища
    storage.ts             # localStorage: load/persist, генерация id
    model.ts               # ЧИСТАЯ логика: computeElimination, selectPodium, nextAutoAction (+ model.test.ts)
    useWheelGame.ts        # хук: всё состояние игры + действия (+ useWheelGame.test.tsx)
  hooks/                   # переиспользуемые хуки
    useLatest.ts           # стабильный геттер актуального значения (защита от устаревших замыканий)
    useWheelAnimation.ts   # requestAnimationFrame-анимация спина
    useMemes.ts            # загрузка и показ случайных мемов
  lib/                     # чистые помощники (без React)
    share.ts               # сборка/разбор ссылки ?users=[...] с потолками (+ share.test.ts)
    memes.ts               # манифест мемов, случайный выбор
    confetti.ts            # залпы конфетти
    yandexMusic.ts         # парсинг ссылки ЯМ + src плеера (+ yandexMusic.test.ts)
  participants/            # фича «список участников»
    AddParticipants.tsx    # добавление списком
    ParticipantList.tsx    # полный список + шапка (+ ParticipantList.test.tsx)
    ParticipantRow.tsx     # строка участника
  wheel/                   # фича «колесо и результаты»
    wheelModel.ts          # ЧИСТАЯ геометрия: сегменты, выбор по весам, целевой угол (+ wheelModel.test.ts)
    wheelDraw.ts           # ЧИСТАЯ отрисовка на canvas
    Wheel.tsx              # canvas-колесо: связывает модель, анимацию и мемы (+ Wheel.test.tsx)
    SpinButton.tsx         # центральная кнопка / мем-оверлей
    WheelControls.tsx      # длительность + чекбокс авто-прокрутки
    ResultPanel.tsx        # результат последнего спина + «Новый раунд»
    WheelStage.tsx         # композиция сцены
  music/                   # фича «Яндекс Музыка»
    useMusicPlayer.ts      # состояние формы/плеера
    MusicPlayer.tsx        # карточка
    YandexPlayerFrame.tsx  # iframe
```

## Правила разработки

- **Компоненты маленькие и однотипные.** Один компонент — один файл.
- **Состояние игры — в `game/useWheelGame.ts`.** Компоненты получают данные/действия через пропсы
  и не хранят бизнес-состояние. Локальное состояние фичи (плеер, мемы, анимация) живёт в своём
  хуке рядом с фичей — это не исключение из правила, а другой слой.
- **Чистое отделяем от React.** Всё, что можно посчитать без хуков, идёт в `model.ts`,
  `wheelModel.ts`, `wheelDraw.ts`, `lib/` — и покрывается тестами `*.test.ts` рядом.
  Побочные эффекты (конфетти, таймеры) остаются в хуке.
- **Тесты двух видов.** `*.test.ts` — чистые функции, без DOM. `*.test.tsx` — хук игры и компоненты
  через Testing Library в jsdom (`renderHook`, `render`). Поведение со временем (авто-прокрутка)
  проверяется фейковыми таймерами, а не ожиданием. Заглушки окружения — в `src/test/setup.ts`,
  не плодить их по файлам.
- **Типы — в `game/types.ts`**, не дублировать их в компонентах.
- **localStorage — только через `game/storage.ts`.** Прямо в компонентах не писать.
- **Избегать устаревших замыканий**: для значений, читаемых из колбэков (например, анимация),
  используй `useLatest`. Это критично — из-за этого уже был баг с «не останавливающимся авто-спином».
  Сам `useLatest` кладёт значение в ref из `useInsertionEffect`: **писать в ref прямо в теле рендера нельзя**
  (конкурентный React вправе отбросить проход).
- **Производное — считать, а не хранить.** Подиум, активный пул и колесо выводятся из
  `participants` + `eliminatedIds` через `useMemo`/чистые селекторы. Дублирующего состояния,
  которое надо «не забыть обновить», быть не должно.
- **id участников — `crypto.randomUUID()`** (см. `storage.ts`), никаких счётчиков.
  Побочных эффектов внутри `setState(prev => …)` не устраивать: в StrictMode апдейтер вызывается дважды.

## Ключевая бизнес-логика

- **Выбивание** = персистентный список участников + per-session `eliminatedIds`.
- **`enabled` (✋/🙈)** — ручное постоянное «участвует/не участвует», персистится. Выбивание `enabled` НЕ трогает.
- **Вес ×2** — вдвое более широкий сектор, то есть вдвое больший шанс **вылететь**.
- **Подиум** — не состояние, а выборка `selectPodium(participants, eliminatedIds)` **по id**:
  при двух активных 3-е место у последнего выбитого, при одном — он сам 1-е, двое последних выбитых 2-е и 3-е.
  Поэтому он сам пересчитывается при 🙈 и удалении.
- **Во время спина список участников заблокирован** (`locked`): состав, по которому выбран
  победитель, не должен меняться до конца вращения.
- **Авто-прокрутка** — чекбокс включает режим, но последовательность стартует только по кнопке «Крутить»;
  между спинами пауза `AUTO_SPIN_PAUSE_MS`, на победителе режим выключается сам.
- **localStorage персистит ТОЛЬКО состав и `enabled`** (id + имя + ✋/🙈).
  Вес, выбывшие, подиум и настройки сцены — нет: это состояние раунда, оно должно уходить с перезагрузкой.

## Документация

- Пользовательские сценарии — в `user-flow/` (README.md + по одному `.md` на флоу).
  **Меняешь поведение — правь соответствующий флоу в том же коммите.**
- Разделы «Известные ограничения» в флоу описывают поведение **как есть**. Если чинишь описанное
  там ограничение — убирай запись из документа.

## Деплой/бандл

- Сборка через Vite в `dist/`, публикация — `.github/workflows/deploy.yml` (пуш в `main`).
- `base: './'` — относительные пути, работает из подпапки GitHub Pages. SSR нет.
- В `public/memes/` лежит ~10 МБ MP4 и `manifest.json`; они уезжают в бандл как есть.
